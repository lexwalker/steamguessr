# SteamGuessr

Угадайка в духе GeoGuessr: выпадает случайная игра из Steam, нужно угадать, сколько у неё отзывов. Статический сайт на React + Vite, без бэкенда. Датасет собирает Node-скрипт из открытых данных Steam и SteamSpy.

## Запуск

```bash
npm install
npm run dataset        # собрать датасет (см. ниже), можно прервать и продолжить позже
npm run dev            # http://localhost:5173
```

Живая версия: **https://lexwalker.github.io/steamguessr/**

## Деплой

Репозиторий: https://github.com/lexwalker/steamguessr. Каждый push в `main` собирает сайт и выкладывает его на GitHub Pages через workflow `.github/workflows/deploy.yml` (источник Pages: GitHub Actions). Датасет `public/data/games.json` хранится в репозитории, поэтому после пересборки датасета его нужно закоммитить и запушить:

```bash
npm run dataset
git add public/data/games.json
git commit -m "Обновить датасет"
git push
```

Локальная сборка: `npm run build`, папку `dist` можно положить на любой статический хостинг. Пути в сборке относительные, работает из любой подпапки.

## Режимы

- **Классика**: 5 раундов, логарифмический ползунок от 1 до 5 миллионов, до 5000 очков за раунд. Подсказки (теги, дата и цена, Metacritic) открываются за часть очков раунда. Пулы: «Микс», «Хиты» (от 20 000 отзывов), «Середина», «Хардкор» (меньше 300).
- **Дейли**: один и тот же набор из пяти игр для всех на текущую дату. Результат сохраняется локально, повторно сыграть нельзя.
- **Больше / Меньше**: две игры, у правой отзывов больше или меньше, чем у левой. Считается серия и рекорд.
- **Дуэль по ссылке**: адрес партии содержит сид (`?mode=classic&pool=mix&seed=abc123`). Друг открывает ту же ссылку, получает те же игры, сравниваете очки.

Очки за раунд: `5000 × max(0, 1 − |log10((ответ + 1) / (правда + 1))| / 1,5)` минус стоимость открытых подсказок. Попадание в два раза даёт около 4000, промах в десять раз около 1700, в тридцать раз и дальше ноль.

Статистика (лучший результат, серия, дейли) хранится в `localStorage` браузера.

## Датасет

`npm run dataset` (скрипт `scripts/build-dataset.mjs`):

1. Берёт список игр: страницы SteamSpy `all` (топ по владельцам, по 1000 игр на страницу) плюс случайные игры из поиска магазина для «хвоста».
2. Для каждой игры запрашивает `appdetails` (название, описание, картинки, цена, дата), `appreviews` с `language=all` (точное число отзывов, то же, что в строке «Все обзоры») и SteamSpy `appdetails` (теги, оценка владельцев).
3. Пишет `public/data/games.json`. Файл перезаписывается каждые 20 игр, так что сайтом можно пользоваться, пока сбор идёт.

Результаты по каждой игре кэшируются в `scripts/cache/apps/`, повторный запуск докачивает только недостающее. Лимиты Steam: около 200 запросов `appdetails` за 5 минут, поэтому 1000 игр собираются примерно за 30 минут.

Полезные ключи:

```bash
node scripts/build-dataset.mjs --limit=500            # не больше 500 новых игр за запуск
node scripts/build-dataset.mjs --spy-pages=0,1,2,3,4,5 --tail=1500
node scripts/build-dataset.mjs --lang=english --cc=us # язык описаний и регион цен
node scripts/build-dataset.mjs --rebuild              # только пересобрать games.json из кэша
```

Чтобы пересобрать список игр заново, удали `scripts/cache/pool.json`.

## Структура

- `src/App.jsx` — переключение экранов, разбор адреса (режим, пул, сид).
- `src/components/` — `Home`, `ClassicGame`, `GameCard`, `GuessSlider`, `RoundResult`, `Summary`, `HigherLower`.
- `src/lib/scoring.js` — очки, шкала ползунка, пулы и подсказки; `rng.js` — сидированный генератор; `data.js` — загрузка и выбор игр; `storage.js` — статистика.
- `src/app.css` — тёмная тема в духе Steam.
- `design/` — исходники дизайн-канваса (артборды экранов и два альтернативных направления).

## Что не делается и почему

Продажи и вишлисты Steam не публикует, доступны только сторонние оценки, поэтому игра построена вокруг числа отзывов и других открытых метрик. Запросы к Steam из браузера чужого домена заблокированы (нет CORS), поэтому данные собираются скриптом заранее, а сайт читает готовый JSON.
