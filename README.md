# SteamGuessr

Угадайка в духе GeoGuessr: выпадает случайная игра из Steam, нужно угадать, сколько у неё отзывов. Статический сайт на React + Vite, без бэкенда. Датасет собирает Node-скрипт из открытых данных Steam и SteamSpy.

## Запуск

```bash
npm install
npm run dataset        # собрать датасет (см. ниже), можно прервать и продолжить позже
npm run dev            # http://localhost:5173
```

Живая версия: **https://lexwalker.github.io/steamguessr/**

## Деплой

Репозиторий: https://github.com/lexwalker/steamguessr. Каждый push в `main` собирает сайт и выкладывает его на GitHub Pages через workflow `.github/workflows/deploy.yml` (источник Pages: GitHub Actions). Датасет `public/data/games.json` хранится в репозитории, поэтому после пересборки датасета его нужно закоммитить и запушить:

```bash
npm run dataset
git add public/data/games.json
git commit -m "Обновить датасет"
git push
```

Локальная сборка: `npm run build`, папку `dist` можно положить на любой статический хостинг. Пути в сборке относительные, работает из любой подпапки.

## Режимы

- **Классика**: 5 раундов, логарифмический ползунок от 1 до 5 миллионов, до 5000 очков за раунд. Теги, дата, цена, разработчик и Metacritic видны сразу, прячется только оценка владельцев SteamSpy (она выдаёт ответ). Пулы: «Микс», «Хиты» (от 20 000 отзывов), «Середина», «Хардкор» (меньше 300).
- **Дейли**: один и тот же набор из пяти игр для всех на текущую дату. Результат сохраняется локально, повторно сыграть нельзя.
- **Больше / Меньше**: две игры, у правой отзывов больше или меньше, чем у левой. Считается серия и рекорд.
- **Дуэль по ссылке**: адрес партии содержит сид (`?mode=classic&pool=mix&seed=abc123`). Друг открывает ту же ссылку, получает те же игры, сравниваете очки.
- **Вместе** (мультиплеер как в GeoGuessr): хост создаёт лобби, остальные входят по коду или ссылке `?mode=mp&lobby=КОД`, до 8 игроков. Хост выбирает пул, число раундов и время на ответ (10–30 секунд, по умолчанию 20: улики видны сразу, долго думать не над чем). Все видят одну и ту же игру и общий таймер; когда все ответили или время вышло, показывается сравнение: маркеры игроков и правды на шкале, таблица за раунд и общий счёт. Если игрок не успел, отправляется его текущее положение ползунка. В конце итоговая таблица, хост может запустить ещё партию.

В каждом раунде два вопроса: число отзывов (до 5 000 очков) и бонус за процент положительных отзывов (до 1 000, ноль при промахе на 30 пунктов). Пулы: по числу отзывов («Микс», «Хиты», «Середина», «Хардкор») и по тегам Steam («Хорроры», «Стратегии», «Кооп», «RPG», «Шутеры», «Симуляторы»). Дейли считает серию дней подряд.

Очки за число: `5000 × max(0, 1 − |log10((ответ + 1) / (правда + 1))| / 1,5)`. Попадание в два раза даёт около 4000, промах в десять раз около 1700, в тридцать раз и дальше ноль. Бонус: `1000 × max(0, 1 − |разница процентов| / 30)`.

Статистика (лучший результат, серия, дейли) хранится в `localStorage` браузера.

## Оформление

Тёмная тема в духе магазина Steam: зелёная главная кнопка, синие второстепенные, оценка отзывов в фирменных цветах Steam (синий, бежевый, красный). Все цвета и отступы вынесены в переменные в начале `src/app.css`.

## Языки

Интерфейс переведён на 11 языков: русский, английский, китайский (упрощённый), японский, корейский, немецкий, французский, испанский, португальский (Бразилия), польский и турецкий. Выбор языка в шапке (кнопка с флажком). Порядок определения: `?lang=xx` в адресе, потом сохранённый выбор, потом язык браузера, иначе английский.

Строки интерфейса лежат в `src/lib/locales.js` (плоские ключи, множественное число через `Intl.PluralRules`), числа и даты форматирует `Intl` по тегу языка. Описания игр хранятся отдельно от `games.json`, по файлу на язык: `public/data/desc/<lang>.json` (id → короткое описание со страницы Steam на этом языке), файл подгружается при выборе языка. Их собирает `node scripts/build-dataset.mjs --descs` через `IStoreBrowseService/GetItems` (по 100 игр за запрос, все языки за несколько минут); та же команда даёт английские теги Steam играм, у которых SteamSpy тегов не знает, и английские жанры тем, у кого тегов нет вовсе. Теги Steam всегда английские.

## Датасет

`npm run dataset` (скрипт `scripts/build-dataset.mjs`):

1. Берёт список игр: страницы SteamSpy `all` (топ по владельцам, по 1000 игр на страницу) плюс случайные игры из поиска магазина для «хвоста».
2. Для каждой игры запрашивает `appdetails` (название, описание, картинки, цена, дата), `appreviews` с `language=all` (точное число отзывов, то же, что в строке «Все обзоры») и SteamSpy `appdetails` (теги, оценка владельцев).
3. Пишет `public/data/games.json`. Файл перезаписывается каждые 20 игр, так что сайтом можно пользоваться, пока сбор идёт.

Результаты по каждой игре кэшируются в `scripts/cache/apps/`, повторный запуск докачивает только недостающее. Лимиты Steam: около 200 запросов `appdetails` за 5 минут, поэтому 1000 игр собираются примерно за 30 минут.

Полезные ключи:

```bash
node scripts/build-dataset.mjs --limit=500            # не больше 500 новых игр за запуск
node scripts/build-dataset.mjs --spy-pages=0,1,2,3,4,5 --tail=1500
node scripts/build-dataset.mjs --lang=english --cc=us # язык описаний и регион цен
node scripts/build-dataset.mjs --rebuild              # только пересобрать games.json из кэша
node scripts/build-dataset.mjs --enrich=movies        # добавить id трейлеров играм, собранным без них
```

Трейлеры: Steam отдаёт в API только потоковые манифесты, но по id ролика на CDN по-прежнему лежат файлы `movie480_vp9.webm` и `movie480.mp4`, их и показывает галерея. Скриншоты и трейлер открываются во всплывающем окне со стрелками и клавиатурой.

Чтобы пересобрать список игр заново (например, добавить страницы SteamSpy или больше случайных игр), удали `scripts/cache/pool.json` и запусти сборку с нужными ключами. Уже скачанные игры не запрашиваются повторно.

В `games.json` стандартные адреса картинок Steam хранятся в коротком виде (обложка выводится из id игры, скриншоты по хэшу), полный адрес восстанавливает `src/lib/data.js`. Так 7 тысяч игр весят около 5 МБ, а с gzip на GitHub Pages примерно 1 МБ.

Скрипт `scripts/watch-and-push.ps1` умеет следить за долгой сборкой и сам коммитить и пушить датасет: каждые +1000 игр и в конце. Запуск в фоне:

```powershell
Start-Process powershell -ArgumentList '-ExecutionPolicy Bypass -File scripts\watch-and-push.ps1' -WindowStyle Hidden
```

## Структура

- `src/App.jsx` — переключение экранов, разбор адреса (режим, пул, сид).
- `src/components/` — `Home`, `ClassicGame`, `GameCard`, `GuessSlider`, `RoundResult`, `Summary`, `HigherLower`.
- `src/lib/scoring.js` — очки, шкала ползунка, пулы; `rng.js` — сидированный генератор; `data.js` — загрузка и выбор игр; `storage.js` — статистика, стрик, имя игрока.
- `src/lib/net.js` и `src/lib/mp.js` — мультиплеер. Связь идёт через публичный MQTT-брокер по WebSocket (EMQX, запасные HiveMQ и Mosquitto): одна тема на лобби, хост держит состояние игры и публикует его сохранённым сообщением, поэтому опоздавшие и перезагрузившие страницу сразу получают текущее состояние. Своего сервера нет, ответы игроков идут в открытом виде по теме лобби, это игра для своих. Если публичный брокер станет ненадёжным, слой `net.js` можно заменить на свой релей (например, Cloudflare Worker), остальное не меняется.
- `src/app.css` — тёмная тема в духе Steam.
- `design/` — исходники дизайн-канваса (артборды экранов и два альтернативных направления).

## Что не делается и почему

Продажи и вишлисты Steam не публикует, доступны только сторонние оценки, поэтому игра построена вокруг числа отзывов и других открытых метрик. Запросы к Steam из браузера чужого домена заблокированы (нет CORS), поэтому данные собираются скриптом заранее, а сайт читает готовый JSON.
